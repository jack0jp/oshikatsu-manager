# 権限設計とRLSの検証

権限に関わるコード(RLSポリシー、アプリ層の権限判定、参加登録・招待・削除まわり)を触る前に読むこと。

## 前提

権限制御は**二重**に行う。

| 層 | 役割 | テストでの扱い |
|---|---|---|
| Supabase RLS | 最終防衛線。アプリ層をすり抜けても止める | `test/db/` で実DBに対して検証 |
| アプリ層のpure関数 | 主たる判定ロジック。UIの出し分けにも使う | `test/unit/` で検証 |

**両方に同じマトリクスを実装し、両方をテストする。**片方だけ直された状態を検出するため。

## 権限マトリクス

これが正。ここを変更したら、同じPRで両層の実装とテストを変更すること。

| 操作 | オーナー(登録者) | 参加登録済みの他ユーザー | 無関係のユーザー |
|---|---|---|---|
| イベントの閲覧 | ○ | ○ | ○ (全ユーザー共有カタログ) |
| イベントの編集 | ○ | × | × |
| イベントの削除(論理) | ○ ※制約あり | × | × |
| 自分の参加登録・取りやめ | ○ | ○ | ○ |
| 他人の参加登録を取りやめ | × | × | × |
| 他ユーザーの招待 | ○ | ○ | × (参加登録が前提) |
| 自分のステータス変更 | ○ | ○ | — |
| 他人のステータス変更 | × | × | × |
| 自分の公開設定の変更 | ○ | ○ | — |
| 他人の参加情報の閲覧 | 公開設定が公開の場合のみ | 同左 | 同左 |
| 自分の支出の閲覧・編集 | ○ | ○ | — |
| 他人の支出の閲覧 | × | × | × |

**イベント削除の制約:** オーナー本人以外の参加者が1人でもいる場合は削除不可。

**参加登録の公開設定の既定値: 非公開。**

### システム管理者(`profiles.is_admin`)について

**MVPではこの表に管理者の列を作らない。**`is_admin` カラムは
`docs/data-model.md` で定義するが、**これを参照する権限判定はRLSにもアプリ層にも書かない**。
したがってこの表に空欄はなく、フェーズ1の時点でマトリクスは完全である。

フェーズ2で管理者による強制削除を実装するときは、以下を**同じPRで**行う。

1. この表に「システム管理者」の列を追加する
2. RLSポリシーを追加する
3. アプリ層のpure関数に分岐を追加する
4. 両層のテストに列を追加する(2と3のどちらか片方だけ実装された状態を検出するため)

実施タイミングは `docs/roadmap.md`「フェーズ2バックログ」を参照。

## 削除時の支出データの扱い

| ケース | 予算のみ(実績未登録) | 実績が登録済み |
|---|---|---|
| ユーザーが参加を取りやめた | 該当ユーザーの支出データも削除 | 支出データは残す |
| オーナーがイベントを削除した | 参加者の支出データも削除 | 支出データは残す |

考え方: 予算は実施前の見込み値なので消えても影響が小さいが、実績は家計の記録として意味を持つため保全する。イベントは論理削除なので、支出から辿ってイベント名は常に参照できる。

**この分岐はpure関数として切り出し、4通りすべてをテストする。**

## RLS検証の必須要件

`test/db/` で Supabaseローカル(`supabase start`)に対して実行する。

### 1. service_roleキーを使わない

service_roleはRLSをバイパスする。これで通ったテストは、**RLSポリシーを全部削除しても緑のまま**になる。
必ず実際にサインインしたユーザーのクライアントで検証すること。

### 2. 「弾かれること」を確認する

正常系だけのテストは、権限が全開放されていても通る。否定側が本体。

```
// これだけでは何も検証していない
expect(await asUserA.from("expenses").select()).toHaveLength(3);

// これが本体
expect(await asUserB.from("expenses").select()).toHaveLength(0);
```

### 3. マトリクスを表のままテストに写す

上の表の×が1つでもテストされていなければ、それは検証されていない権限とみなす。
表に行を追加したら、テストにも行を追加する。

### 4. 壊して赤くなることを確認する

新しく書いた権限テストは、**対応するRLSポリシーを一時的に無効化して赤くなるか**を確認してから戻す。
確認しない限り、テストが機能しているかは永遠に分からない。

## 最小の検証セット

| 検証 | 期待 |
|---|---|
| 他ユーザーの支出を読む | 0件 |
| 非公開の参加登録を他ユーザーが読む | 0件 |
| オーナー以外がイベントを更新 | 失敗 |
| オーナー以外がイベントを削除 | 失敗 |
| 他ユーザーの参加ステータスを変更 | 失敗 |
| 他人の参加登録を勝手に取りやめる | 失敗 |
| 参加者がいるイベントをオーナーが削除 | 失敗 |
| 参加登録していないユーザーが他人を招待 | 失敗 |

## なぜここを最優先するか

権限の漏れは**例外を投げない**。見えてはいけないものが、エラーなしで、それらしく表示される。
ユーザーが気づくまで誰にも分からない種類の失敗なので、先に潰す。
